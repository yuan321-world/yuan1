# 验证码请求与发送状态验收

日期：2026-10-15，Asia/Shanghai。用户确认方案后实施，仅阶段1认证补强，未进入阶段2。

## 实现

- 保留后端账号启用、已验证邮箱关联检查。不匹配公开请求零投递，继续返回相同202、ACCEPTED、随机challengeId、有效期及冷却，不提供公开投递状态查询。
- 修复不匹配请求作废真实验证码：仍经过相同数量的数据库调用、限流及异步排队，但不执行真实证明失效更新，也不调用SMTP。
- 当前身份与密码验证通过后，账户绑定提前返回EMAIL_TAKEN，不入发送队列。GET /api/v1/account/email-codes/{challengeId}仅允许当前用户、BIND用途和安全版本匹配；no-store，未登录401，其他归属/用途/不存在统一404。
- V4只追加delivery_state列与CHECK，不改已执行V1—V3。记录QUEUED/SMTP_ACCEPTED/FAILED/NOT_SENT，查询另依据到期和禁用信息返回EXPIRED/FAILED；无邮箱/验证码/SMTP细节泄露。
- 前端要求明确ACCEPTED后才启动请求间隔，按钮改为「请求中／再次请求」。429遵循Retry-After，网络或503不伪造成功。忘记密码提示仅匹配才发信，允许继续编辑，不呈现匹配结果。
- 绑定状态自动查询最多15次、每2秒一次；失败局部提示并禁用该证明。网络可手动检查状态，不自动重发POST；编辑邮箱、接收新请求、绑定成功或离开页面取消旧查询，忽略迟到响应。SMTP接受不承诺收件。
- 保留5分钟、5次错误、一次性消费、重发替换、持久限流、CSRF、Session、security_version及角色规则，无新依赖。
