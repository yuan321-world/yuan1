# 用户管理方案与原型（已确认并完成正式实现）

2026-10-27用户已审阅原型，讨论并同意停用限制后要求继续。按前文建议去掉管理端重置指引，首版保留账号查询、详情、停用/恢复和管理记录；本轮进入正式实施计划阶段，尚未改变真实账号。目标是让管理员找到账号、判断状态并协助处理登录问题。密码保持现有不可逆哈希，任何管理响应/日志/页面均不返回原密码、哈希、验证码、Token。

## 范围与选择

建议首版采用账号列表＋详情弹窗＋单个操作确认，复用现有后台导航、白底细边框、黑色主按钮及柔粉提示。比直接在表格编辑更能看清对象与原因；暂不做批量停用或角色修改，降低误操作并保持首版清晰。原型保留数据、文章、专项、整卷、留言、账户设置入口，新增用户管理。

列表按账号/昵称/ID搜索，按状态与角色筛选，分页、空态、清空筛选；显示账号、昵称、角色、启用状态、注册时间。详情附遮罩邮箱、验证状态、账号记录与管理记录。展示数据均为原创虚构演示，刷新重置，不读取真实账号。未有可靠最近登录记录，不臆造最近活跃字段。

普通用户可停用/恢复，必须输入1–200字管理原因并确认。明确告知停用阻止登录/刷新/写操作、保留学习与留言记录，不自动删除或隐藏发言。恢复仅恢复登录资格，不恢复旧会话。首版所有ADMIN及当前管理员账号只读，服务端复核，避免锁死管理员；不提供删除账号/修改角色/直接代设密码。

密码找回保留现有用户自助邮箱验证流程。管理端不提供发送指引、查看验证码、代设密码或绕过身份验证入口。账号停用不影响匿名公开浏览；需登录的保存练习、提交作答、AI批改、发帖、点赞、评论等受限。已受理的后台任务不自动撤销或退款，此版只阻止停用提交后新发起的需鉴权操作。

## 正式接入建议（本轮未实现）

仍为Vue3/Pinia、Java21/Spring Boot/MyBatis-Plus/MySQL模块化单体，identity模块扩展，不增框架。候选接口 `/api/v1/admin/users` 列表/详情、`/{id}/status` 状态写入、`/audit`记录。仅真实ADMIN，写操作保留CSRF与来源检查；DTO白名单、ID字符串、分页、no-store、统一错误。账号列表不选取password_hash，邮箱默认遮罩。

新增Flyway迁移保存管理审计/幂等结果（执行时核对最高版本，本轮不预占V31）。命令含UUID、expectedVersion与原因；审计记录操作者/对象/前后状态/原因/时间/命令号，不记录凭据。并发修改409保留输入，同命令重试不重复操作/邮件。

停用与恢复均递增既有security_version；现有TokenAuthenticationService每次解析检查enabled及securityVersion，旧access/refresh立刻不可用，恢复不能使旧会话复活。数据库状态与审计同事务，以安全版本使旧会话失效，无需扫描或立即物理删除Redis记录。保留历史学习/内容；匿名公开阅读仍按原业务规则。

正式实现复用现有身份校验，无需扫描Redis全部会话。以数据库enabled及递增security_version为安全边界，旧Redis会话记录可按既有TTL到期；恢复同样递增版本，不会恢复旧Token。停用提交前已经通过权限检查的请求可能完成，不宣称跨全部业务即时中止在途请求。

## 验收与边界

本轮只验证独立原型的搜索/分页/空态、详情、停用恢复原因、受保护账号、不再提供管理重置与审计显示、窄屏/键盘。正式实现需真实库验证普通用户/匿名403或401、服务端ADMIN保护、停用旧access/refresh失效、恢复旧会话仍无效、并发/幂等/事务、跨用户隔离和日志无凭据。原型成功不能替代真实权限验证。
