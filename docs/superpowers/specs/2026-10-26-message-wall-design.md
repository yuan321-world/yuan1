# 留言墙：学习交流方案（待审阅）

2026-10-27更新：用户已确认方案及正式实施计划，正式模块已实现；后文“待审阅/原型”表述为历史设计记录。当前验证与本地部署状态见 [正式验收](../../acceptance/2026-10-27-message-wall.md)。

已由用户明确确认：用途为学习交流，分享心得、打卡与互相鼓励；登录用户发布后立即公开，管理员后续处理。以下细节为本轮建议，尚未实现正式业务，不宣称验收通过。

## 界面与范围

沿用原型便签画布，复用正式黑白灰/柔粉界面；便签六种柔和颜色只限留言内容区。桌面拖动空白平移、滚轮/按钮缩放、双击或明确按钮发帖；手机默认列表，键盘用户可切换列表。保留搜索、只看我的、回到我的便签、点赞、平铺评论、举报、本人删除及后台编辑/删除的原型能力。长文卡片截断，详情完整阅读。首页占位接到/wall，管理端增加留言管理入口。

按用户补充截图，桌面以整块点阵画布为主：左上显示名称/条数，右上放轻量分类与列表切换，底部集中搜索、定位我的、我的留言、说明和发布；右下横排缩放与查看全部。便签按ID保持散落位置，点赞/筛选不打乱；新便签发布后定位到新内容。保留站长管理员标识及欢迎便签。窄屏列表优先保证文字可读，不强迫缩放小字。

用户追加确认的原型调整：双击画布空白后填写便签，发布于双击位置附近；按当前平移/缩放换算画布坐标，若会碰到其他公开便签，向附近空位避让。原型按实际渲染尺寸（含标题/旋转余量）和30画布像素间隙放置，既有便签不移动，取消不产生空白记录。工具栏发布同样寻找空位；查看全部覆盖新便签范围。正式版若跨用户共享坐标，需要服务端事务分配并处理并发碰撞，不能依赖本原型内存布局证明并发安全。

管理员增加“发布公告便签”：独立标题（最多80字符）、公告标识、醒目边框/顶线和管理员身份；正文支持选中文字加粗，预览使用受限的 `**文字**` 语法，普通留言仍为纯文本。原始HTML始终转义，公告展示只生成允许的strong元素，不开放任意HTML。正式版公告创建/修改须额外校验服务端ADMIN和格式白名单；账号显示名不能充当管理员资格。公告无自动置顶、自动跳出或系统通知，本轮不扩展这些能力。

原型：[message-wall-preview.html](../../prototypes/message-wall-preview.html)。原始原型不变；新原型全部为内存演示，刷新重置，没有演示登录冒充服务端鉴权。旧积分入口保留明确演示说明，不擅自引入真实积分规则。

保留“向AI”演示入口及能力说明，通用助手本轮未接服务；已有写作/翻译AI批改仍从正式练习入口使用。原型不外呼模型或消耗额度。管理原型演示留言编辑/隐藏/恢复/删除、评论隐藏/恢复/删除及举报记录；正式操作理由、版本冲突、限流、分页和鉴权留待实施，不将内存演示视为后端验收。

建议游客可读公开内容，登录后发帖/点赞/评论/举报；昵称来自本人账号显示名，客户端不能伪造作者。分类为学习心得/每日打卡/加油鼓励，另有管理员公告类型。正文1–1000 Unicode字符、评论1–500，普通内容只用纯文本与换行，公告只额外允许加粗；不渲染用户HTML或自动插入媒体。所有具体长度及限流待本方案审阅后落实。

## 用户流程

发帖选择分类、颜色并输入内容，确认后立即显示；使用UUID幂等请求防重复提交，失败保留文字，未确认结果先查询再重试。本人可确认删除自己的留言/评论；管理员可处理全部内容。公开列表只包含VISIBLE；删除为逻辑删除。隐藏/删除后不再接受点赞、评论或举报。

点赞采用明确liked=true/false目标状态，唯一(user,message)记录，重复请求不会叠加；列表显示本人点赞状态。评论为一层讨论，分页加载，保留整条留言上下文。长文在详情展示，关闭恢复原列表/画布位置。举报可针对留言或评论，原因及补充说明交给管理员；同用户同目标未处理举报复用，举报本身不自动隐藏内容。

“我的留言”可查看公开/已隐藏状态和管理员给作者的理由，隐藏内容不通过公开列表/直链泄漏。本人已删除内容不继续公开，学习记录不因留言操作发生变化。

## 管理端

按公开/隐藏/删除及待处理举报筛选。管理员可查看上下文、隐藏、恢复隐藏内容、保留并处理举报，删除须确认。保留原型编辑能力：填写原因，保存原文/新文/操作者/时间，公开标注“管理员已编辑”；不悄悄冒充原作者。原型的“保存并处理举报”对应一个明确事务操作，不隐式清理其他无关举报。评论同样可单独隐藏/删除及处理举报。

所有管理写操作服务端校验ADMIN，不能通过前端演示角色开关授权。使用内容版本号防覆盖；旧版本冲突返回409，用户已删除内容不能被迟到编辑重新公开。

用户追加要求：处理原因通知作者，并在用户界面提供铃铛消息入口。管理员编辑/隐藏/删除留言或评论时，拆为“告知作者的原因”（必填）和“内部备注”（选填，仅管理员可见）。前者只给内容作者看，不向其他用户公开；后者只写管理审计。通知描述具体处理和原因，不能将所有编辑直接定性为违规。恢复展示也通知作者。

位置按用户最新标注：铃铛从全局导航移到留言墙底部工具栏的发布加号旁，仅留言墙学习视图显示。列表/手机视图放在底部跟随滚动的留言工具条，不出现在管理界面，也不扩展到其他页面。

原型已提供铃铛未读数字、我的消息、逐条/全部标为已读、公开内容查看入口；隐藏/删除内容没有公开跳转，保留作者本人消息中的短摘要和原因。游客不读消息，当前林同学演示只看到林同学的处理通知，其他作者的通知不混入。消息仍仅在当前页面内存，刷新重置，不能当成真实权限隔离。

正式版增加wall_notification：接收用户、内容类型/ID、处理类型、作者可见原因、处理时短摘要、创建/已读时间及管理操作唯一关联；不包含内部备注。管理变更、审计、通知创建在同一数据库事务完成，幂等重放不重复通知。消息GET/标已读均从服务端会话限定接收者，按稳定游标分页；隐藏/删除后公开直链保护不因通知而绕过。该消息提醒是站内拉取，本阶段不引入邮件、WebSocket或系统推送。

## 数据和接口草案

保持现有Vue/Pinia + Java21/Spring Boot + MySQL模块化单体，新增wall业务包，不引入WebSocket、消息队列或AI审核。数据库为业务事实，Pinia只保存页面/过滤/画布及草稿交互状态。

当前最高迁移V29；正式实施前重新核对，新增迁移，绝不改写旧迁移。建议表：wall_message、wall_comment、wall_like、wall_report、wall_moderation_log、wall_request。父子归属FK、点赞唯一键、未处理举报唯一约束、内容版本和VISIBLE/HIDDEN/DELETED状态在库/业务两层保护。管理员编辑日志保留前后文本，日志接口仅管理员可访问。

建议API均在/api/v1：

- GET /wall/messages：关键词、分类、mine及稳定游标分页；GET /wall/messages/{id}和/comments读取详情。
- POST /wall/messages、POST /wall/messages/{id}/comments：UUID幂等创建；作者来自服务端会话。
- PUT /wall/messages/{id}/like：目标liked状态；DELETE本人留言/评论带版本与幂等标识。
- POST /wall/reports：目标类型/ID、原因、说明、请求ID。
- /admin/wall/messages、/comments、/reports：管理员列表与版本化处理命令，管理操作写审计记录。
- GET /wall/notifications，PUT /wall/notifications/{id}/read，PUT /wall/notifications/read-all：本人消息和幂等已读；全读需以请求时的明确消息边界处理，不误标后到消息。

匿名只读不暴露邮箱/登录凭证/举报人；所有写操作沿用JWT身份、来源校验和CSRF保护。普通用户不得查看举报人及管理内部记录。纯文本按Vue转义输出，服务端不接受自报userId/role/likeCount/status。

建议发布30秒冷却、每天10条；评论5秒冷却、每天60条；举报每天10次且未处理同目标复用。按服务端用户计数、北京时间切日，不依赖浏览器。具体限额作为方案参数供用户调整，不在本轮原型中假装实施。

画布位置为当前视图布局与浏览偏好，不允许任何用户移动/修改他人的内容；按已加载ID稳定分配位置，过滤和互动不无故打乱画布。分页载入和空/加载/失败状态独立处理，手机列表不依赖二维坐标。

## 实施与验收边界

本轮只交付方案和可点击原型，待视觉/范围审阅后写实施计划，按完整全栈流程逐项交付。正式实施必须同时完成学习端、最小管理端、迁移、真实数据库及双端验证，不能只补假数据页面。

关键检查：游客写入401；他人删除404/403且无改动；普通用户后台403；CSRF失效拒绝；发帖重放只产生一条；点赞并发唯一；评论与父帖归属；隐藏/删除直链不可见；举报隐私与去重；管理员过期版本冲突；长文/恶意HTML/emoji字符计数；鼠标/键盘与320px操作；失败保留草稿，原学习业务指纹保持。
