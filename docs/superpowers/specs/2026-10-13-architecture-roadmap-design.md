## 1. 目标与已知约束

2026-10-15用户后续明确选择JWT + Redis，覆盖本文早期Cookie Session/暂不引入Redis的建议。目标架构以[认证迁移设计](2026-10-15-jwt-redis-auth.md)为后续细化入口，认证迁移已于2026-10-16通过本地验收并切换，见 [验收](../../acceptance/2026-10-15-jwt-redis-auth.md)。Vue/Java/MyBatis/MySQL及阶段0—6业务顺序保持，认证迁移在阶段2业务实现前完成。

建设一个可以长期迭代的 Java 英语学习平台，复用现有 Lingua Loop 原型的视觉方向，打通阅读、查词、生词收藏、复习和考试专项训练。

用户已经提供综合平台方案和静态前端原型，并要求先确定技术栈与开发阶段。本方案暂以大学生的四级学习和阅读训练作为首版主线；六级、高考、雅思等保留为后续扩展，目标人群可以在评审时调整。

正式开发工作目录为 `D:\codex\English Hero`，检查时该目录为空。原型位于 `D:\codex\English Learner\prototype\index.html`，作为设计参考，保留原文件。产品展示名暂沿用 Lingua Loop，仓库工作名为 English Hero，最终命名不影响架构。

V1 验收目标：用户登录后能够阅读文章、查询词义、收藏带来源语境的生词、完成复习，再完成一组四级阅读题并查看解析和重做错题；数据刷新后可恢复，管理员能维护下一批内容。

## 2. 架构选择

推荐前后端分离、同域部署、模块化单体：一个 Vue 应用包含独立的学习端和管理端布局，一个 Spring Boot 应用按业务模块组织代码，一个 MySQL 保存业务数据。

其他路线的取舍：

- Java 服务端渲染可以减少前后端接口工作，但本项目有划词弹窗、学习卡片、答题状态等交互，采用 Vue 更便于延续原型。
- 微服务适合独立扩容和多人团队，本项目早期拆分会增加部署、鉴权和事务协调工作，暂不采用。

浏览器通过 `/api/v1` 调用 Java；生产环境由 Nginx 提供前端文件并转发 API，开发环境由 Vite 代理 API。前端路由采用 history 模式，部署时配置回退到入口文件，页面地址能直接访问和刷新。

后续 Python 负责批处理、分句和词形分析，输出经过校验的数据；用户、学习记录、考试成绩的业务写入仍由 Java 管理。

## 3. 技术栈基线

| 层次 | 选择 | 使用约定 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite | 使用单文件组件与 Composition API |
| 路由与状态 | Vue Router、Pinia | 页面对应真实路由；Pinia 保存用户与当前交互状态，数据库负责持久化 |
| HTTP | 浏览器 Fetch，封装一个请求入口 | 统一处理会话失效、错误信息和请求取消 |
| 学习端 UI | 原型设计变量、CSS、业务组件 | 保留黑白主色、玫红强调色和英文阅读排版；组件样式避免全局类名冲突 |
| 管理端 UI | Element Plus，按需引入 | 用于表格、分页、表单、弹窗，主题与品牌保持一致 |
| 前端工具 | Node.js 24 LTS、pnpm 11.25.0 | 复用已验证的工具；精确依赖版本锁入 pnpm-lock.yaml；CI 使用 pnpm install --frozen-lockfile |
| 后端 | Java 21、Spring Boot 4.0.8 基线、Spring MVC | 阻塞式常规 Web 应用；依赖版本由 Boot 管理，后续评估同系列补丁升级 |
| 构建 | Maven Wrapper | 固定构建工具版本，统一开发与 CI 命令 |
| 认证与授权 | Spring Security、RS256 JWT、HttpOnly刷新Cookie、项目专用Redis | Access仅在内存；MySQL检查账号版本/角色，Redis检查登录family及期限 |
| 数据库 | 部署目标 MySQL 8.4 系列；本地先复用已有 MySQL 8.0 服务 | utf8mb4，时间统一保存为 UTC；本地先核查服务端版本，公开部署前验证 8.4 迁移 |
| 数据访问 | MyBatis-Plus 3.5.17 | 使用 mybatis-plus-spring-boot4-starter；复杂统计保留明确 SQL |
| 数据迁移 | Flyway | Boot 4 使用 spring-boot-starter-flyway，并引入 org.flywaydb:flyway-mysql；表结构由版本化迁移维护 |
| 接口文档 | OpenAPI、springdoc-openapi 3.1.1 | 官方说明 3.x 支持 Boot 4；阶段 0 实测文档生成与 Swagger UI |
| 验证 | Boot 测试框架、Vitest、Playwright | 测试鉴权、数据隔离、复习规则、判分及核心浏览器流程 |
| 部署 | Docker Compose、Nginx | 部署阶段引入；阶段 0 原生运行 Java、Vue 和已有 MySQL，容器工具不作为前置条件 |

版本说明：方案编写时这是待联调的兼容基线；2026-10-14阶段0已完成依赖及真实数据库联调。后续仍需保持并验证 Java、数据库驱动、MyBatis-Plus、Flyway、springdoc 和前端工具的组合，再把精确版本写入构建文件。不得使用 SNAPSHOT 或预览版本作为产品依赖。

2026-10-13 环境核查：JDK 21.0.12.1 已安装在 `C:\Java\jdk-21.0.12.1`，但当前默认 JAVA_HOME 为 JDK 17。临时指定 JDK 21 后 Maven 3.9.9 正常运行；Node.js 24.19.0、Git 2.47.1 和 Codex 自带 pnpm 11.25.0 已验证。MySQL80 服务运行且 127.0.0.1:3306 可连接；客户端版本 8.0.41，服务端版本及数据库账号尚未通过登录验证。npm 和可运行的 Docker 未发现，WSL 状态查询返回 E_ACCESSDENIED，不能据此判断 WSL 未安装。

以下为被2026-10-16迁移覆盖的历史选择：Cookie Session 是针对首版浏览器产品的早期推荐，替代原方案中默认的 JWT。前后端分离不要求 JWT；服务端会话便于退出和失效处理。保留 CSRF 防护，生产 Cookie 设置 HttpOnly、Secure 和合适的 SameSite。普通登录与“保持登录”的有效期分别明确，过期后回到登录页面。未来有移动客户端或第三方调用时再评估 token 方案。

基础设施按需求引入：

- 阶段 2：本地词典查询、有限缓存；第三方翻译服务通过 Java 适配接口接入，失败不阻断阅读。
- 阶段 5：音频存储先通过统一存储接口接入本地持久化目录，再按部署需求切换兼容对象存储；数据库保存文件元数据和引用。
- Redis：在缓存需求或多实例部署有实际需要时引入，不作为 V1 启动条件。
- Python：先做离线工具；需要在线调用时再增加 FastAPI。
- AI：阶段 6 接入；服务密钥只保存在后端，调用失败可回退到词典或参考解析。

## 4. 目录与模块边界

建议目录结构，在对应阶段创建，当前文档不创建业务骨架：

```text
English Hero/
  frontend/                 Vue 学习端与管理端
  backend/                  Spring Boot 应用
  tools/                    后续数据处理脚本
  infra/                    Compose、Nginx、部署说明
  docs/                     产品方案、阶段设计、接口和验收记录
```

后端按 `identity`、`content`、`dictionary`、`vocabulary`、`practice`、`learning`、`community`、`assistant` 划分业务包，只在对应阶段创建。每个业务包内部包含接口、服务和数据访问。后台通过受保护的业务接口维护内容，复用业务校验，避免另建一套重复逻辑。

公共层只放错误处理、分页、鉴权基础配置和必要的基础工具。模块通过服务方法调用，不跨模块直接修改数据表。初期使用一个 Maven 应用，不为每个业务包创建独立进程。

首版数据模型按阶段迁移：用户与角色；文章与文章版本；词典词条；用户生词与来源；学习状态与复习日志；题组与题目；练习记录与作答。收藏、复习与判分涉及的唯一性约束和事务必须写进各阶段设计。

## 5. 阶段交付

各阶段以“可演示的用户流程 + 持久化 + 必要验证”交付。先完成当前阶段验收，再开展下一阶段；不提前建完所有表或实现全部后台。

### 阶段 0：工程基础与前端结构

交付：锁定依赖版本；前后端骨架；MySQL 开发配置；Flyway；健康检查；接口文档；学习端与管理端布局；基础路由和设计变量。

本阶段只创建系统元数据表和迁移历史，不提前创建用户、词库、题库等业务表。真实登录与数据库会话表属于阶段 1；未实现的业务页使用明确的待开发状态。阶段 0 管理端仅预览空布局，不提供管理数据或修改接口。

整理原型：修复留言便签与学习提示共用 `.note` 的样式冲突；缩小登录后首页品牌区；手机端提供可发现的导航；移除尚未实现功能的可用承诺。原型演示数据与真实 API 分开，生产不启用演示账号逻辑。

验收：前端构建及类型检查通过，后端能启动并连接数据库；从空库执行迁移成功；浏览器能调用健康接口；390px 和桌面宽度下基础布局可用，直接访问路由与刷新正确。

### 阶段 1：真实账号与权限

交付：注册、登录、退出、当前用户、会话失效反馈、用户/管理员角色、账户设置和后台入口。阶段 1 使用用户名注册；邮箱验证与找回密码在 V1 对外开放前补齐，内测阶段通过受控方式管理测试账号。

密码由后端使用 Spring Security 的密码编码器保存。管理员由部署过程创建，用户不能通过注册或修改客户端状态获得管理员权限。个人记录按登录用户隔离。

验收：重启后仍能登录原账号；有效持久会话按配置恢复；退出后会话不可继续使用；未登录返回 401，普通用户调用管理接口返回 403；用户不能访问他人的私有记录。

### 阶段 2：文章阅读、查词与生词收藏

交付：文章列表、分类、阅读详情、今日推荐、阅读进度；查词弹窗、词形关联、明确的收藏操作；后台文章草稿、预览、发布、下架及导入校验。

第一批准备至少 10 篇有明确使用来源的文章和可查词的数据。内容显示真实来源，演示文章单独标识。查询词义不自动收藏；收藏保存基本词形、原文形式、原句和文章版本。重复收藏合并词条、保留来源。手机端验证文本选择与弹窗操作。

验收：管理员发布的文章出现在学习端，下架文章不能开始新阅读；查词成功、未找到及请求失败均有明确反馈；刷新后收藏及阅读进度恢复；重复收藏不产生重复学习任务。

### 阶段 3：新词学习与间隔复习

交付：一个四级词书、生词本、学新词、到期复习、记忆反馈、今日任务和基础学习统计。

首次采用确定的间隔规则，保存规则版本、复习日志和下次复习时间。反馈分“忘记、模糊、记得”，学新词限量与复习量分别设置。遗忘词安排再次练习，积压复习分批展示。若后续采用 FSRS，单独评估与迁移，不将原型展示的算法名称视为已实现。

验收：收藏词可进入学习队列；反馈改变下一次复习安排；刷新与重复提交不会重复记录同一次反馈；模拟日期跨天时到期列表正确；今日任务数量和统计来自实际记录。

### 阶段 4：四级阅读专项训练，交付 V1 内测版

交付：仔细阅读题组、网页答题、答案保存、交卷、客观判分、解析、错题本与重做；后台题组录入、预览、发布和基本导入校验。准备至少 10 组经过校对的阅读练习，支持原创或有明确使用依据的内容。

先实现共用阅读材料 + 多个单选小题，从实际能力中提炼题库结构。练习中允许查词，交卷前默认不显示答案。服务端判分；同一次练习重复交卷只产生一个最终结果；历史作答关联当时的题目版本。成绩先显示正确数与正确率。

验收：刷新后答案恢复；重复交卷结果一致；发布后改题不改变历史结果；错误题目可查看原作答并开始新一轮重做；学习端完整闭环可演示。

阶段 4 是首个可持续使用的版本。外部公开上线前补齐邮箱验证、密码找回、登录接口限流、HTTPS、备份恢复演练，以及本阶段核心流程在部署环境的验证。

### 阶段 5：听力与整套模拟考试

交付：先扩展选词填空、匹配等阅读题型，再加入听力题组、音频播放与专项复读；题型齐备后组装整套试卷，提供答题卡、服务端截止时间、自动保存、自动交卷、成绩报告和答题恢复。

训练模式允许辅助功能；模拟模式关闭查词、解析和训练专用播放控制。多页面答题冲突有明确处理；断网显示保存状态，恢复后同步；到期后只接受截止时间前已经保存的答案，避免以客户端时间决定是否超时。听力中断后的恢复策略在该阶段单独设计。

验收：音频与题组对应正确；刷新不重置考试时限；断网、重复交卷、超时和多页面场景符合规则；客观题与主观题结果分开展示；未评价的主观题不会生成完整总分。平台估分标识清楚。

### 阶段 6：智能辅助与可选扩展

按独立小版本交付，而非一次完成：

1. Python 内容清洗、分句、词形处理工具，结果经后台审核后发布。
2. AI 上下文词义与写作/翻译参考评价，展示依据、估计性质与失败重试入口。
3. AI 学习建议只读取当前用户有权访问的记录，默认不修改设置。
4. 留言墙作为可选社交功能，包含举报、管理审核、长文本处理和手机上的列表视图。
5. 扩展六级，再根据用户需求评估高考、雅思等独立考试规则。

验收：每项扩展分别定义验收；第三方服务不可用不影响已完成的基础学习能力；AI 不泄露其他用户记录；用户界面隐藏内部工具函数名和开发调试信息。

## 6. 各阶段统一完成标准

- 前后端实际接口联通，业务结果进入数据库；演示数据明确隔离。
- 涉及内容维护的阶段同步完成最小后台。
- 页面具备加载中、空数据、请求失败与操作成功状态；会话失效有恢复入口。
- 对鉴权、数据归属、复习和判分等关键行为做自动化验证；不为纯样式调整增加重复测试。
- 提交数据库迁移、启动说明和验收记录；不把“接口写完”当作阶段完成。
- 关键用户流程检查桌面和手机；键盘焦点及表单错误提示可用。
- 危险的内容删除提供确认或撤销；历史学习与考试记录不因内容下架而被清除。
