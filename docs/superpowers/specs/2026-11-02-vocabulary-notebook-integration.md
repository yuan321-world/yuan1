# 背单词与笔记本融合设计

> 当前状态：2026-11-02用户已批准并授权完整实施，正式模块与本地运行已更新，见[正式验收](../../acceptance/2026-11-02-vocabulary-complete.md)。下文保留设计阶段历史描述。

日期：2026-11-02。状态：用户已确认方案，简版独立原型已制作并通过45项三端检查，用户于2026-11-02明确确认“可以就这样设计”，设计与原型定稿；正式功能未实施。

用户目标：把独立笔记本纳入背单词模块，在同一处收藏、管理和学习单词/词组。本次只设计，不改导航、页面、后端或数据。

## 1. 当前事实

正式NotebookView已有：收藏生词列表/分页、加入学习、取消收藏、中文与英文词典释义、多个文章来源及原句、回到指定文章版本和选区。取消收藏保留来源和已加入学习的复习记录。

目前没有正式词组实体/词组本，也没有个人备注编辑功能，不能称其为搬迁已有能力。当前独立升级原型的生词本/手动熟练只使用隔离本地演示数据。

## 2. 推荐信息结构

主导航保留“背单词”，通过它进入统一词汇空间。确认后的新版导航不再单列笔记本；旧`/notebook`地址仍可抵达生词本，旧收藏记录与来源链接继续有效。

模块内固定三页签：

| 页签 | 主要职责 | 主要操作 |
| --- | --- | --- |
| 今日学习 | 选词书、目标、新学/复习、继续保存轮次 | 开始新学、开始复习、切词书 |
| 生词本 | 管理从阅读、练习和学习中收藏的单词 | 查看详情/来源、加入学习、标记熟练/恢复复习、取消收藏 |
| 词组本 | 管理固定搭配与短语，以及独立的学习状态 | 收藏词组、编辑个人释义、查看来源、加入词组练习、取消收藏 |

学习记录、计划和熟练免复习管理保持次级入口，不再新增主导航项目。手机三页签横排，使用相同容器/标题位置；切页签仅替换内容，搜索/过滤在各自页签保留，避免布局跳动。

## 3. 生词本页面

顶端：搜索单词或中文释义；来源筛选（全部/阅读/专项/学习中）；收藏时间排序；学习状态筛选。仅出现有实际记录的来源类别，不填充虚假分类或计数。

列表行：单词、音标、主要中文义、收藏来源数、学习状态、更多操作。桌面采用紧凑列表，手机纵向卡片；详情在抽屉打开，手机使用全屏抽屉，关闭回到原列表位置。

详情保留固定双语例句、短语、分义近义词、原文例句/文章来源和定位链接。按最新偏好，不重复展示冗长英文definitionEn；不删除英文例句。个人备注可在后续新增，但不是当前已有能力。

“生词本页签”与词书选择里的“我的生词”使用同一收藏集合：前者用于管理，后者是新学选词范围，不维护两份单词列表。

## 4. 收藏与学习保持不同含义

| 操作 | 收藏变化 | 学习/复习变化 |
| --- | --- | --- |
| 加入生词本 | 加入或恢复收藏，重复操作不重复计数 | 不自动加入学习，不重置阶段/到期时间 |
| 加入学习 | 保持收藏 | 未加入的词建立个人学习关系；已有词共用原进度 |
| 标记熟练 | 保持收藏与来源 | 全局免自动复习，跳过当前题；不冒充独立回忆成功 |
| 恢复复习 | 保持收藏 | 已学词恢复原计划；未学词重新可进入新学 |
| 取消收藏 | 从收藏列表移除，来源可恢复 | 不删除或重置已加入学习的历史/复习计划 |

“是否收藏”“是否加入学习”“是否手动免复习”“是否到期”分别保存，界面不能强塞成互斥状态。收藏数、今日新学数、手动熟练数和通过数分别统计。同一用户同一词条跨词书共用掌握与免复习状态。

## 5. 词组本页面与能力边界

建议词组卡片以`look forward to`为例：英文搭配、中文释义“期待”、固定结构或使用提示（有依据才展示）、收藏原句与来源、加入练习/取消收藏。单词与词组不混算今日新词数量。

阅读/练习中划选后保留原有“翻译/解析”，另外提供显式“收藏词组”。收藏前可调整选区和个人中文释义，防止把整段文章或任意两个词自动当固定搭配。词典短语区域同样可显式收藏；句子依旧保留为来源例句。

有参考释义直接复用；已有翻译结果可作为个人释义草稿。没有可靠释义时允许用户填写，标明个人备注；不默默调用百度或AI补齐。语法解析与收藏动作各自独立。

词组独立实体/归一化文本/个人收藏/多来源记录，与词典单词entry分开。相同规范短语多次遇见合并收藏，来源逐条保留；不通过拆成单词或绕过DictionaryRules实现词组本。

词组学习建议先支持看词组回想中文、按中文默写完整词组；沿用看词手动继续、提示后回队、手动免复习等交互原则。目标与统计单独称“词组”，不挤占单词新词额度。首版不自动生成AI例句、语法或判定任意近义表达正确。

## 6. 串联用户路径

1. 阅读点击完整单词 → 完整词典卡 → 加入生词本 → 在生词本查看来源或加入学习。
2. 背词遇到有用/难记词 → 加入生词本 → 输入、轮次、原计划保留。
3. 遇到简单词 → 手动熟练 → 留在收藏里，后续自动复习排除；可在管理页恢复。
4. 划选固定搭配 → 收藏词组 → 确认片段与释义 → 词组本 → 主动加入词组练习。

有保存轮次时进入收藏管理先保存/暂停，返回时恢复原词书、队列、前缀和失败证据；跨页签不能重新取词覆盖轮次。来源文章暂不可用时保留原句快照并说明，不抹掉收藏。

## 7. 分期与验收

先改独立原型：固定三页签、生词列表/来源抽屉、词组示例、收藏与加入学习区别，以及返回轮次。旧笔记本入口保留跳转，未接入服务明确演示；待用户确认视觉与交互。

正式交付分两条完整闭环：先融合已有生词收藏—来源—加入学习—复习；再单独做词组收藏—来源—加入—练习。词组本首轮只在原型中演示，不以生产空页签冒充上线；若两者分期发布，生产词组入口标注待开放，不提供无效按钮。

实施时保持现有Vue/Pinia、Java21、MySQL/Flyway架构，复用既有鉴权、归属、分页/来源接口。新词组结构与手动免复习状态通过新增迁移和独立实施计划落实，不改写既有迁移/收藏数据。

必须验收：历史收藏/多来源不丢、旧地址可到达、收藏与复习解耦、跨词书去重、免复习可恢复、保存轮次不被管理操作覆盖、词组不污染单词统计、权限与用户隔离、三端页签/抽屉可操作。

设计阶段核对了现有NotebookView与升级设计；后续仅实施独立原型，见融合原型验收。未修改正式业务，用户已确认当前原型布局与流程，正式数据/服务仍待实施验收。
