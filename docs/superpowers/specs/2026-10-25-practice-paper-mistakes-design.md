# 整卷错题归集与复习设计（待评审）

日期：2026-10-25。状态：用户已回复“确认”批准本方案，实施计划已编写、待评审及执行方式选择；尚未实现、迁移或修改业务数据。

## 目标和现状

用户同意继续补齐整卷错题归集与复习。成功标准是：交卷后的客观错题能在整卷错题本看到、能回看原卷、能按适合该题型的范围重练，答对后转为已订正；已有单项错题和整卷成绩、冻结版本继续有效。

已核对当前源码与V19—V26迁移：

- 整卷只保存一份 `practice_paper_attempt` 及七个response，不创建七份单项轮次。
- `practice_mistake` 的来源、最近轮次均外键引用单项 `practice_attempt`，不能将整卷ID填进去；单项和整卷ID可能相同，不能靠一个无类型ID推断来源。
- 单项仔细阅读只重做错题；听力、选词、匹配分别重练完整25/10/10题以保留语境。单项错题已有PENDING/RESOLVED、错误次数及冻结版本。
- 当前 `practice_attempt` 的MISTAKES进行中唯一约束按用户、题组生效；来源整卷的重练不能错误复用其他版本或单项来源的未完成轮次。
- 最新迁移为V26；新增迁移拟用V27，实现前再次核对编号。

写作、翻译当前没有客观判错，不纳入本功能。此次不引入AI批改、六级、阅读打卡或新的技术框架。

## 方案选择

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| 将整卷错题直接塞进原单项错题表 | 一个统一台账 | 必须改变既有非空外键及来源语义，牵动原重做接口；不推荐 |
| 每次列表读取时临时解析所有整卷结果JSON | 不新增归集表 | 订正状态、错误次数和分页越来越复杂；不推荐 |
| 独立整卷错题台账，复用现有练习播放器 | 保留单项表和接口，来源可追溯、事务与分页明确 | 需新增来源关系和迁移；推荐 |

推荐第三种。它仍属于practice模块，使用现有Vue、Pinia、Java21/Spring/MyBatis/MySQL；不新增独立服务。整卷下增加“错题本”栏目，保持现有单项错题本入口及含义，避免用户把两类不同来源的记录误认为重复数据。

## 用户可见流程

1. 整卷交卷后，错误和未答的客观题自动归集；主观题不计入。全部答对时没有伪造的错题。
2. 整卷目录显示“全部试卷 / 我的练习 / 错题本”。错题本沿用紧凑卡片、考试年月筛选和待订正/已订正筛选；增加题型筛选，按原卷题号显示“听力第1题”“仔细阅读第46题”等。
3. 卡片显示原卷标题、题型、题号、错误次数、原答/参考及分行双语解析；“查看原卷”打开本人已提交的原卷并定位到相应部分/题目。
4. 整卷结果页在存在客观错题时提供“复习本卷错题”，进入仅与本次原卷错题范围相关的列表。已经订正的条目仍可切换状态查看，不删掉原卷错误结果。
5. 从错题卡点击重练时才创建一份真实重练轮次，复用现有单项播放器。仔细阅读重做该来源阅读篇中的待订正错题；听力完整重练原25题、保留完整音频与片段；选词/匹配完整重练原10题。按钮明确写出重练范围。
6. 新重练交卷后，相关整卷错题答对转为已订正，仍错/未答保持待订正并累计错误次数。原卷分数与作答不变；重练记录有“来自整卷”标记，可返回来源。

页面复用现有布局与组件，不新造一套视觉体系；手机保留筛选弹窗、题型导航和听力题号导航。

## 归集、版本和历史规则

- 整卷台账以 `(userId, setVersionId, questionId)` 去重。同一冻结题在多次整卷中做错，累计次数；不同发布版本独立，不能把新版本答案或解释覆盖到旧题。
- 单项台账继续独立，单项练习的答对/答错不隐式改写整卷台账，反之亦然。整卷来源的重练只更新整卷台账。
- 保存首次错误的原卷、槽位、原题号和冻结题组/试题版本，以及最近一次评估来源、时间、状态和错误次数。原始整卷response继续保留所有来源事实，不复制或篡改原答案。
- 后续同一冻结题在整卷或整卷来源重练中答对，可将现存待订正条目标为已订正；此前没有错题的正确题不新增台账。按服务端提交顺序更新，重复请求不重复累计。
- “本卷错题”范围从本人该次已提交的冻结结果提取最多55个客观题ID，再匹配台账；不只按首次错误原卷筛选，以免同题多次做错后漏掉来源。
- 纳入已有真实整卷历史：迁移从已完成轮次的冻结结果按完成时间/ID顺序重放归集，保留首次错题及最近状态，幂等、不创建任何模拟作答。进行中整卷和写作/翻译排除。旧结果JSON、原判分及已发布内容不修改。

## 数据与接口边界

拟新增 `practice_paper_mistake`：用户、冻结题组版本、quiz版本、题目ID组成受约束的题目身份，唯一键使用上述去重身份；来源整卷/槽位、原题号、首次错误时间、最近评估来源、状态、错误次数等字段支持本人状态和年月分页。

在 `practice_attempt` 增加可空的来源整卷ID和槽位，缺省为空，保留既有kind枚举与单项来源列。新增外键校验来源归属，校验单项来源/整卷来源不能同时存在。只有用户主动点击重练才创建MISTAKES轮次，不因归集自动制造单项成绩。已有行和单项DTO字段保持；新来源信息使用可选字段，前端有来源时才显示。

复用现有冻结问题及整卷组件关系，数据库外键与服务端都检查用户、整卷、槽位、题组版本、quiz版本和题号映射的一致性。JSON中的ID不能绕过这些校验。原卷题号根据槽位和原冻结题序计算，不能依赖题干恰好包含数字，更不能把错题子集的第1题当原卷第1题。

新增接口均在 `/api/v1`：

- `GET /practice/paper-mistakes`：本人分页，考试/年月/题型、PENDING/RESOLVED，可选sourceAttemptId限定本卷；标题、来源、题号、解释均来自本人已完成冻结内容。
- `POST /practice/paper-attempts/{id}/retry-mistakes`：本人已完成原卷，载荷 `{requestId, slot}`；服务端决定可复习题集，不接收客户端任意题ID/版本；返回既有单项Attempt及可选整卷来源信息。
- 保存、提交、播放票据继续使用既有单项轮次接口，服务端根据可信来源关系选择台账；客户端不能指定“替谁订正”。

既有 `/practice/mistakes`、单项retry和整卷启动/草稿/提交的原请求契约不变。`PracticePaperAttemptService.submit`只在首次事务提交中追加归集；幂等重放直接返回结果。归集失败必须与原卷提交一起回滚，不能产生已交卷却漏归集或未交卷先有错题的状态。

同用户同题组已有重练时，只有来源类型及冻结版本相同才允许恢复；否则返回409并提供本人可继续的轮次入口，提示先完成现有练习。不抢占或覆盖旧轮次，不削弱现有唯一约束。

下架后仍可依本人已完成冻结来源复习；素材与音频继续走原鉴权票据，旧版引用不能替换为当前公开版本。未登录401、他人来源404、非法槽位/状态400、无错题或活动冲突409；所有写请求保留CSRF及乐观锁/请求幂等。

## 验证标准

实施时先写有意义的失败测试，再实现；至少包含：

- 同卷重复/并发提交只累计一次，失败归集和原卷交卷完整回滚。
- 55题不同错/空组合准确归集，主观题排除；重复冻结题去重，新版本独立。
- 历史回填仅真实已完成数据，前后旧作答与冻结内容一致；迁移重复启动不重算次数。
- 他人列表/原卷/重练/音频不可访问，伪造来源、槽位、跨版本题目拒绝。
- 仔细阅读子集保留46—55原题号；听力25题、选词和匹配10题保留语境及音频分段。
- 重练正确转已订正、错误累计，原卷成绩不变，原单项错题与重练行为不变。
- 已有活动轮次的同版本恢复与跨来源/版本409，无本地草稿覆盖。
- 专用测试库实际1440/320px完整流程：整卷交卷→整卷错题本→查看原卷定位→重练→保存刷新→交卷→已订正；旧单项流程回归。

新增Flyway迁移，不改V19—V26；同步API、数据库、使用说明、进度和验收记录。执行前后明确记录迁移/集成/构建与视觉检查，不能将Mock替代真实库，也不在开发学员账号创建测试成绩。
