# QQ邮箱发送验证码：本地配置

2026-10-16：认证已接入JWT + Redis，配置见 [认证配置](auth-jwt-redis-setup.md)。QQ SMTP、验证码存储/限流、防枚举与账号邮箱匹配规则不变；本轮认证测试仅用测试邮箱，不重复向QQ发送邮件。

仅用于阶段1邮箱注册、绑定和找回密码，认证仍为用户名/密码和持久Session。邮箱不作为登录名。

## 配置步骤

1. 在QQ邮箱网页版设置中开启SMTP服务，按提示生成SMTP授权码。不同版本的设置名称可能不同，以邮箱当前的「账号与安全／授权码」界面为准。
2. 将 `backend/config/application-mail.example.yml` 复制为同目录 `application-mail.yml`（若已生成则直接编辑）。后者被Git忽略，正常启动会自动加载。不要把实际配置复制到聊天、截图或提交。
3. 填写 `spring.mail.username` 为完整QQ邮箱；`spring.mail.password` 填SMTP授权码；`english-hero.email.from` 填相同的发件邮箱。不要用QQ登录密码。
4. `hmac-secret` 使用至少32字节的随机私密值，已生成的本地文件会自动提供；保存后不要每次启动重新生成，否则既有验证码会失效。不要与邮箱授权码共用。
5. 将 `english-hero.email.enabled` 改为 `true`，重启后端。仅预览前端或仍未填写时保持false；已有账号仍可登录，发送验证码返回503「邮件服务暂不可用」。

QQ SMTP使用 `smtp.qq.com:465`，SSL与认证开启。连接、读取、写入超时均设置，不能开启邮件协议debug以免日志暴露验证码或授权信息。配置依据：[腾讯官方邮件连接器说明](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。

## 验收

- 先用登录后的「账户设置」给现有账号绑定邮箱。输入当前密码并发送验证码，到邮箱收件后输入并确认，页面显示已验证邮箱。管理员在后台账户页完成同一流程。
- 注销，使用「忘记密码」，填写用户名与已验证邮箱，收到验证码后设置新密码；应返回登录，旧密码不可用，其他设备旧会话失效。
- 新注册账号须完成邮箱验证码；不会自动登录，不能使用邮箱代替用户名登录。
- 找回入口统一提示「若账号与已验证邮箱匹配，验证码将发送」；统一接受响应不代表实际投递成功。检查收件箱和垃圾邮件，未收到时冷却结束后重发。
- 首版只提供首次邮箱绑定，不开放更换已验证邮箱，避免未经设计的账户恢复通道。

验证码不在页面、接口、服务器日志中提供，无法通过查看数据库取得明文。异步投递失败会使本次验证码失效；SMTP填写正确并实际收件才算真实QQ邮件联调成功。自动测试的内存投递器、回环SMTP收件器与QQ真实投递分别记录，不相互替代。

本地开发启动与测试见 [阶段1说明](phase-1-setup.md)。生产环境仍需HTTPS及Secure Cookie，并通过受控环境变量/私密配置管理邮件授权信息。
