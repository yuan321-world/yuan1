# Lingua Loop 消息反馈与表单错误规范

## 认证弹窗补充（2026-10-16）

游客可访问首页，但不能请求个人阅读推荐或绕过受保护路由。旧/login、/register、/forgot-password仅作兼容地址，统一回首页打开对应弹窗，不再显示左右分栏页面。复用表单、错误映射、验证码和密码组件。字段错误仍在字段下、整体错误在当前表单、网络故障在弹窗内可重试；认证失败不能改成Toast或关闭弹窗。

遮罩不关闭；发送、提交及重连期间禁止关闭。切换/取消保留本页面草稿和真实冷却，认证成功后销毁缓存；密码不写浏览器持久存储。验证背景inert、滚动锁定、焦点约束及关闭后返回。手机长表单内部滚动，键盘操作可达。首页移除计划/打卡，后续归入登录后学习统计。见[验收](acceptance/2026-10-16-auth-modal.md)。

日期：2026-10-15（Asia/Shanghai）。

## 状态与范围

这是用户要求整理的全站反馈规范。**用户已确认方案，本轮已接入登录、注册、找回密码及账户设置相关表单。** 实现与测试边界见 [本轮验收](acceptance/2026-10-15-form-feedback.md)；后续模块仍需按各自范围实现并验证。

优先适用于登录、注册、找回密码、账户资料、邮箱绑定/验证码、修改密码；阶段2阅读模块沿用本规范。保持现有黑白灰与柔和粉色设计，复用Vue组件、结构化API错误和现有Element Plus依赖，不改认证接口、数据库、密码规则、验证码规则、角色鉴权及会话机制。

## 反馈位置与分类

| 类别 | 展示位置与行为 | 示例 |
| --- | --- | --- |
| 字段校验错误 | 对应输入框下方，错误边框，文字与输入关联 | 密码长度、两次密码不一致、邮箱格式、验证码错误 |
| 当前表单提交失败 | 当前form内部、提交按钮前的固定反馈区；保持可见直到重试/相关修改，不自动消失 | 登录凭据不匹配、账户状态冲突、当前操作暂不可用 |
| 验证码发送受限/邮件服务故障 | 当前验证码区或当前表单内，配合发送按钮冷却；不放到其他表单或Toast中 | RATE_LIMITED、EMAIL_UNAVAILABLE |
| 操作成功 | 简洁成功Toast，用于无需持续阅读的完成反馈；重要后续指引留在当前步骤 | 昵称已保存、邮箱已验证；改密后需重新登录的说明可保留在登录表单 |
| 网络异常/连接超时 | 所属页面的可恢复提示，保留当前页面和合法身份状态，可重试；一个页面去重展示 | 无法连接服务、请求超时 |
| 会话过期 | 根据UNAUTHENTICATED等结构化信号处理清理/重登，并在登录页说明原因；并发错误只提示一次 | 登录已失效，请重新登录 |
| 权限不足/全局不可用 | 页面级权限或服务状态提示，保留安全边界 | FORBIDDEN、持续系统不可用 |
| 删除、覆盖等重要操作 | 执行前确认弹窗：说明对象和影响，明确取消/确认，默认不落在危险确认按钮上 | 后续阅读模块删除文章、覆盖内容 |

普通保存、验证码请求、密码显隐不加确认弹窗。本轮范围没有删除/覆盖业务入口，不为规范创建虚构功能或无用弹窗。

同一错误只有一个主要展示位置。字段错误不再同时复制到表单顶部、页面顶部或Toast；通用的「请检查填写内容」不重复展示已经定位的字段错误。页面级连接异常不在每张表单中重复播报。

## 校验和恢复交互

1. 首次进入页面不显示红色校验提示。保留现有提交/获取验证码时的校验策略，不在每次输入时新增远程校验请求。
2. 提交或触发局部操作时，校验该操作所需字段；收集适用错误，按表单内DOM顺序定位第一个错误，而不是由校验代码的执行顺序决定焦点。
3. 本地校验已触发后，用户继续输入时仅重新校验相关字段；通过后清除其错误，仍不合法时保留/更新，不因任意一次键入就一律清空。确认密码依赖密码字段，须同步重新判断。
4. 服务端错误绑定当次提交的值。相关值改变后，移除已不适用的服务端错误；用户名/邮箱占用等仍以服务端提交结果为准，不通过额外请求推测占用状态。
5. 邮箱/用户名改变导致既有验证码证明失效，沿用现有证明失效逻辑；在验证码附近说明需要重新获取，不重复弹Toast，不伪称已发送或已验证。
6. 提交失败优先聚焦当前表单的第一个错误输入框，必要时滚动到可见位置；无字段错误时聚焦当前表单的错误容器。不跳到别的表单或页面标题。
7. 不改变密码清理、请求防重复、验证码冷却、禁用状态、角色跳转等既有业务规则。局部反馈状态与局部表单绑定，不为本次提示统一额外重构并发提交策略。
8. 原生required/type=email等约束要保留。若替换浏览器原生气泡为内联提示，必须接管invalid事件并覆盖相同约束；不能只关掉原生校验后漏掉空值/邮箱格式错误。

## 结构化错误映射

现有ApiError已提供status、code、fieldErrors及retryAfterSeconds，直接复用。分类依据字段、错误码、操作上下文和错误类型，不通过匹配中文message决定位置或鉴权行为。

| 信号 | 处理原则 |
| --- | --- |
| fieldErrors中的当前表单字段 | 优先映射到本表单字段；如currentPassword映射到「邮箱验证当前密码」或「改密当前密码」，不能跨表单复用状态 |
| VALIDATION_ERROR | 字段内联；未识别字段回退到当前表单错误，不静默吞掉 |
| BAD_CREDENTIALS + 登录操作 | 当前登录form整体错误，不推断究竟用户名还是密码错误，不触发会话过期流程 |
| BAD_CREDENTIALS + 当前密码校验操作 | 有fieldErrors优先使用；无fieldErrors时可按操作上下文映射到currentPassword，不依赖中文提示 |
| EMAIL_TAKEN、USERNAME_TAKEN | 映射到当前email/username字段；优先采用服务端fieldErrors |
| EMAIL_ALREADY_BOUND、ACCOUNT_CHANGED | 当前表单冲突提示，按现有账号恢复逻辑更新真实状态；不将所有409笼统描述为同一种情况 |
| RATE_LIMITED | 当前操作区域提示，保留Retry-After倒计时；不全页锁死、不重置服务端配额 |
| EMAIL_UNAVAILABLE | 当前邮箱流程说明「邮件服务暂不可用，请稍后重试」，不因503自动把昵称/其他表单判为失败 |
| CSRF_INVALID | 当前操作的可恢复凭据提示及既有重试策略；不是权限不足或会话过期的同义词 |
| UNAUTHENTICATED | 页面级登录失效处理；不能仅凭任意401就判定退出 |
| FORBIDDEN | 权限反馈；不能仅凭任意403就清理登录身份 |
| TimeoutError、网络连接失败 | 页面级可恢复提示，与业务字段错误分开；明确取消的过期请求不当作网络故障反复提示 |
| 未识别错误 | 当前表单或明确的全局作用域兜底；不得显示内部堆栈、请求全文或敏感值 |

错误路由工具只决定展示类型与字段映射，不自行发请求、清理Pinia身份或跳转；真正的会话/权限操作仍由已有认证流程负责。请求层不自动弹Toast，避免页面重复提示，也不改变现有异常抛出契约。

验证码发送接口202仅表示请求已接受，不等于投递或收件成功。注册保留准确的接受提示，找回密码始终保留「若账号与已验证邮箱匹配」的统一响应，不因前端优化泄露账号存在性。本轮不增加投递状态接口或改变异步发送机制。

后续已确认补强（2026-10-15）：有效requestState=ACCEPTED后按钮显示「再次请求」，表示请求频率间隔；找回页明确说明「仅当用户名与已验证邮箱匹配时才会发送验证码」，匹配与否行为一致。账户绑定新增仅本人可查询的发送状态，失败在绑定form内提示，网络在页面级提示，SMTP接受不写成收件成功。上述「本轮不增加」保留为反馈统一任务的历史范围，后续实现以docs/api.md的新契约为准。

## 共用组件与实现约定

- 保留PasswordInput的显隐、输入类型、焦点能力以及invalid/describedBy参数；统一给账户页传入错误状态。
- 保留EmailCodeField的邮件/验证码字段和倒计时，补齐各调用方错误参数；本组件仅处理控件交互，不自行弹全局消息。
- 增加轻量useFormFeedback组合函数：每个form各自持有字段错误、整体错误；统一结构化映射、定向清理、首错聚焦及可见区域滚动。复用现有密码/用户名校验，不增加第二套业务规则。
- 增加小型FieldError和FormFeedback展示组件（实现时可按实际复用程度合并），统一ID、文字、aria关联与布局，不重写整个表单框架。
- 成功Toast优先封装项目已安装的Element Plus消息服务，按需引入对应样式，映射到现有颜色/圆角变量；不新增依赖，不整站更换为Element Plus表单。
- 确认弹窗规范优先复用同一依赖的MessageBox能力，待存在真正删除/覆盖操作时使用；本轮不额外建设未被使用的确认框抽象层。
- 错误映射集中到前端反馈工具中，保留底层ApiError；不同action显式声明字段清单和必要别名。

## 视觉与无障碍

- 输入错误使用既有玫红/柔和粉色边框和说明；正常输入保留原边框，不仅靠颜色表达错误。
- 文案一到两句，说明如何修改，不指责用户，不回显密码、验证码、授权码、Cookie或令牌。
- 错误输入标记aria-invalid=true，aria-describedby包含提示和错误ID；密码错误ID指向真实input而非图标按钮。
- 内联提示和表单反馈采用合适的live区域，不为同一错误制造多个alert。聚焦输入框时能读到错误，动态更新避免重复朗读整个页面。
- 成功Toast不抢焦点，礼貌播报；可关闭，避免连续堆叠；需持续操作的说明不依赖自动消失的Toast。
- 网络/会话提示提供键盘可达的恢复入口；确认弹窗约束焦点、支持取消并在关闭后回到触发控件。
- 320px手机、桌面和长表单均可正常滚动，错误换行不产生横向溢出；保留现有左侧品牌布局与密码图标44px点击区域。

## 实施顺序和验收要求

1. 先复现账户邮箱当前密码错误跑到页顶的问题，建立结构化错误映射和局部表单状态的回归。
2. 实现轻量共用反馈工具/展示组件及成功Toast，再接入账户三个表单。
3. 接入登录/注册/找回/验证码，保留既有业务、认证跳转、防枚举和密码显隐逻辑。
4. 验证字段错误位置/边框/读屏关联，首错聚焦及滚动，修正后错误清理，局部失败不污染其他表单，成功反馈，401/403/429与网络分类，手机长表单和无重复提示。
5. 前端单元测试、typecheck、生产构建及必要桌面/手机Mock浏览器回归，明确不将Mock当作后端鉴权或真实SMTP验收。

阶段2页面在开发前先阅读本文件；查词/收藏失败使用所属区域反馈，网络故障使用页面提示，成功收藏可轻量Toast，删除/覆盖仅在真正有此业务时确认。不得由本规范推定阶段2已获开发授权。

当前复用入口：`frontend/src/feedback/useFormFeedback.ts` 管理每个表单的结构化错误、原生约束、定向清理与首错聚焦；`FieldError.vue` / `FormFeedback.vue` 展示局部错误；`feedback/notify.ts` 封装现有Element Plus成功消息。验证码调用方必须校验本次发送所需字段，再由EmailCodeField管理请求、challenge与冷却。页面「重新连接」仅检查连接，不自动重放验证码或提交请求。


## 统计与阅读状态的自动刷新（2026-10-18）

恢复可见/焦点或项目时区跨日可触发只读刷新，同次事件合并，后台页不持续请求。保留已展示内容，使用aria-busy表示刷新，不把完整内容短暂折叠为加载行；首次无数据才用加载占位。失败明确提示和提供重试，不假称已更新；不能用GET隐式生成学习/打卡记录。身份变化/卸载要取消旧请求、清理监听器与计时器。
